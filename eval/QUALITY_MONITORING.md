# Регулярная проверка качества

## Цикл

Проводить проверку раз в неделю и перед демонстрацией новой версии:

1. Запустить `python -m pytest tests/e2e tests/profile/test_case_data.py -q`.
2. В интерфейсе открыть не менее трёх карточек: заёмщика, вкладчика и компанию без кредитно-депозитной экспозиции. Проверить источник, банковскую цитату и блок «Как получен вывод».
3. Проверить каждый поступивший пользовательский голос через `GET /api/metrics/feedback`. Сводка содержит только количества и долю полезных ответов.
4. Эксперт проверяет holdout-набор `eval/holdout_news.yaml`, заполняет его поля `expert_review` и добавляет запись в `eval/quality_review_log.csv`. Не переносить примеры из holdout в обучающую/настроечную разметку до закрытия цикла.
5. Завести задачу, если есть неподтверждённый факт/число, неверная цитата, ложная персонализация либо оценка любого измерения ниже 3/5. Повторить проверку после исправления.

## Оценка карточки

- **Точность:** факты и даты совпадают с текстом новости.
- **Персонализация:** выводы используют только подтверждённые признаки выбранной компании; гипотеза обозначена как гипотеза.
- **Источники:** цитата банка дословна, содержит документ и страницу; отсутствие материала указано явно.
- **Полезность:** риск, возможность и следующий шаг помогают принять решение и не обещают финансовый результат.

До заполнения holdout-поля экспертом набор имеет статус `pending_expert_review`. Автоматические тесты подтверждают только структуру, трассировку и поддержку утверждений источниками; они не являются заключением банковского эксперта.
