# NewBad — «Что важно для вашей компании»

Сервис собирает новости и рыночные данные, сопоставляет их с профилем бизнеса и сохраняет персональные разборы и диалоги. В приложении один режим работы: вход по логину и паролю, собственный профиль и история для каждого аккаунта.

## Запуск на этой машине

Из каталога `NewBad` запустите `start-manual.bat`: меню позволяет запустить, остановить и перезапустить приложение. Из PowerShell доступны те же действия:

```powershell
.\start-manual.bat start
.\start-manual.bat stop
.\start-manual.bat restart
```

При запуске используются существующий `.env` и локальные базы. Запуск приложения не очищает данные и не пересоздаёт аккаунты.

- Интерфейс: http://127.0.0.1:5173
- API и описание запросов: http://127.0.0.1:8000/docs
- Проверка доступности API: http://127.0.0.1:8000/api/health

## Новая установка

Нужны Python 3.11, Node.js 22 с npm и доступ к репозиториям пакетов при первой установке. Команды выполняются из `NewBad`:

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
.\scripts\dev.ps1
```

Скрипт создаёт `.venv`, устанавливает недостающие Python-зависимости и зависимости интерфейса, запускает API и Vite, затем открывает браузер. Порты 8000 и 5173 должны быть свободны.

На новой установке нет аккаунтов и внешних новостей; банковская аналитика автоматически устанавливается из поставляемой SQLite. Зарегистрируйте аккаунт, заполните профиль компании и запустите сбор данных. Перенесённые ранее три аккаунта находятся только в локальной базе этой машины; исходники не содержат их паролей или автоматического заполнения.

### Запуск отдельных процессов

Для ручной установки зависимостей в Windows:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
npm ci --prefix ui
```

API и интерфейс запускаются в разных терминалах:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --env-file .env --host 127.0.0.1 --port 8000
```

```powershell
npm run dev --prefix ui
```

В Linux/macOS путь к Python окружения — `.venv/bin/python`; для создания окружения используется `python3 -m venv .venv`. Команды npm остаются теми же. При прямом запуске API параметр `--env-file .env` загружает настройки сервера; PowerShell-скрипт `dev.ps1` читает этот файл самостоятельно.

## Первый рабочий сценарий

1. Войдите в аккаунт или зарегистрируйтесь.
2. Проверьте профиль компании: деятельность, географию, показатели, банковские продукты, интересы и контрагентов.
3. Нажмите **«Обновить данные»** в шапке главной страницы или рабочего пространства.
4. Откройте ленту, выберите новость, запустите разбор или откройте обсуждение.
5. Для работы анализа через модель настройте её маршрут в **«Настройках разработки» → «Модели»**.

По умолчанию маршруты задач имеют значение `mock`: внешняя модель не вызывается. Сбор новостей и котировок работает независимо от модели; для подробного разбора, изучения сайта и чата нужно выбрать доступный маршрут.

## Обновление данных и настройки

Кнопка **«Обновить данные»** запускает оба сборщика: новости RSS и котировки MOEX — валюты, акции и металлы. Задание выполняется на сервере и продолжает работу при переходе между страницами и перезагрузке браузера. По завершении открытая лента и рыночные виджеты перечитывают данные. Отображаются успешное завершение, частичный результат или ошибка источников.

Отдельный запуск сохранён в настройках разработчика:

- **«Новости» → «Собрать сейчас»** — сбор публикаций.
- **«Рыночные данные» → «Собрать сейчас»** — сбор котировок.
- При изменённых параметрах кнопка **«Сохранить и собрать»** сначала сохраняет настройки.

В настройках также доступны период сбора, сроки и лимиты хранения, расписания, персонализация, модели по задачам, рекомендации банка и диагностика источников. В «Обслуживании» можно очистить собранные новости с подтверждением. Раздел «Аналитика банка» позволяет искать и читать материалы из базы; карточки новостей показывают подходящую позицию банка отдельно от персональной интерпретации AI.

Кнопка «Добавить материал» открывает форму ручного ввода: название, дата публикации и текст аналитики банка (от 40 символов). Период, примечание и уточнение темы необязательны. Запись сохраняется в общей рабочей SQLite, доступна всем аккаунтам и помечается «Добавлено вручную». Файлы загружать не требуется. В карточке доступны «Редактировать» и «Удалить» с подтверждением удаления. Для материалов кейса полный текст и проверенные оценки редактируются отдельно: весь OCR автоматически не становится подтверждённой позицией банка. Изменения действуют для всех профилей; при следующем открытии ленты подбор пересчитывается. Старые фрагменты сохраняются для истории источников, но исключаются из поиска и нового подбора. Перезапуск и обновление поставляемого корпуса сохраняют правки и не восстанавливают удалённые материалы. Модель для проверки банковских фрагментов задаётся маршрутом «Персональная подборка», для их интерпретации — маршрутами разбора новости и чата. Сохранение и поиск по библиотеке не вызывают модель.

Сбор использует сохранённые параметры; RSS отдаёт ограниченный архив, а источники могут быть временно недоступны. Повторный запуск одного сборщика во время его работы блокируется. Состояние общего задания хранится в памяти процесса: перезапуск API прерывает его, уже сохранённые данные остаются. Блокировки и расписания рассчитаны на один процесс API.

## Профиль, анализ и чаты

Редактор профиля содержит сведения о компании, деятельность, выручку и численность, группу компаний, банковские продукты, финансовые интересы, рынки и контрагентов. Пустое значение отличается от нуля и ответа «Нет». Публичный сайт можно изучить после согласия; предложения с цитатами подтверждаются вручную.

Индекс связи новости объясняет её связь с компанией и не является вероятностью события. Рекомендации банка сохраняются отдельно для пары «профиль — новость». «Мои чаты» позволяют продолжить, найти, переименовать и удалить разговор; диалоги изолированы по аккаунтам.

## Настройки сервера и моделей

Секреты и адреса серверов задаются в локальном `.env`. Образец `.env.example` содержит только параметры, используемые приложением. При изменении `.env` перезапустите API.

| Параметр | Назначение |
|---|---|
| `APP_DB_PATH` | Основная база; по умолчанию `data/app.sqlite3` |
| `DATA_DIR` | Каталог журнала; по умолчанию `data` |
| `LOCAL_LLM_BASE_URL` | OpenAI-совместимый адрес локальной модели |
| `CASE_LLM_BASE_URL`, `CASE_LLM_API_KEY` | Адрес и ключ облачного провайдера |
| `ALLOW_CLOUD` | Разрешение облачных вызовов; дополнительно нужен выбранный маршрут задачи |
| `LLM_MODE` | Общий режим маршрутизатора; маршруты конкретных задач задаются отдельно в интерфейсе |
| `LLM_PLACEMENT` | Политика размещения локальной модели: `auto`, `gpu` или `ram` |
| `LLM_LOG_CONTENT` | Подробное логирование содержимого вызовов модели |
| `APP_ENV`, `AUTH_REGISTRATION_ENABLED`, `AUTH_COOKIE_SECURE` | Окружение, регистрация и параметры cookie |
| `BANK_CORPUS_PATH` | База знаний банка; по умолчанию `data/bank/corpus.sqlite3` |

В интерфейсе настраиваются задачи `real.profile_site`, `real.news_report`, `real.news_selection` и `real.chat`. Для локального маршрута нужен работающий сервер модели; для облачного — адрес, ключ и `ALLOW_CLOUD=true`. Допустимые модели и режимы перечислены в `config/llm.yaml`. При недоступности модели разбор и чат возвращают ошибку с причиной; подборка может использовать правила.

Веса не скачиваются приложением. Описание локального запуска находится в [models/README.md](models/README.md); `scripts/llama-server.ps1` запускает уже установленный GGUF через `llama-server`.

## Хранение и импорт

`data/app.sqlite3` хранит аккаунты, профили, настройки, новости, котировки, анализы, рекомендации и чаты. Пароли записываются как salted scrypt-хэши, токены сессий — как SHA-256. Изменения профиля и ручной сбор данных используют CSRF-токен. Журнал моделей и кэш повторного воспроизведения находятся в `data/journal.sqlite3`.

Рабочие базы с аккаунтами, `.env`, веса моделей и временные результаты OCR не входят в Git. Исключение — поставляемая база знаний `data/bank/corpus.sqlite3`, содержащая только материалы кейса. При переносе на другую машину их нужно переносить отдельно; для копирования баз остановите API. Общий банковский корпус устанавливается из `data/bank/corpus.sqlite3` в рабочую SQLite. PDF, JSON страниц и Tesseract для работы сервиса не требуются. Подробности структуры и качества данных — в [описании корпуса](data/bank/README.md).

Команды обслуживания из корня проекта:

```powershell
.\.venv\Scripts\python.exe scripts/prepare.py
.\.venv\Scripts\python.exe scripts/prepare.py news
.\.venv\Scripts\python.exe scripts/prepare.py bank
```

Первая команда инициализирует и проверяет базу, вторая импортирует RSS, третья устанавливает банковский корпус из SQLite и обновляет персональные привязки. Эти команды читают переменные окружения текущего терминала; `.env` автоматически не загружается. Внешняя папка `DATA/bank_analytics` для запуска не нужна.

## Docker

```powershell
docker compose up --build
```

Compose запускает API на порту 8000 и подключает `./data` и `./config`. Банковский корпус включён в проект; внешние PDF не монтируются. Интерфейс запускается отдельно командой `npm run dev --prefix ui`. Для проверки производственной сборки интерфейса выполните `npm run build --prefix ui`; файлы появятся в `ui/dist/`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check app tests scripts/prepare.py
npm run build --prefix ui
```

Тесты используют временные базы и не изменяют рабочие аккаунты. `scripts/test.ps1` и `scripts/test.sh` устанавливают зависимости и выполняют тесты со сборкой интерфейса. Браузерные сценарии в `ui/tests/chat-workspace.mjs` и `ui/tests/data-refresh.mjs` требуют установленного Playwright и Vite на порту 5175; путь к пакету Playwright передаётся первым аргументом.
