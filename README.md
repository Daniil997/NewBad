# NewBad — «Что важно для вашей компании»

Сервис новостной аналитики для бизнеса: собирает публикации и рыночные данные, сопоставляет события с профилем компании и объясняет возможное влияние с учётом аналитики Альфа-Банка. Рабочие данные хранятся в SQLite.

В приложении один рабочий режим с авторизацией. Каждый аккаунт имеет собственный профиль компании, персональные оценки новостей и диалоги. В настройках разработчика управляются общие источники, маршруты моделей, банковская библиотека и индивидуальные рекомендации для выбранных профилей.

## Возможности

- Профиль компании: деятельность, география, показатели, продукты банка, финансовые интересы, рынки, зависимости и контрагенты. Изучение сайта предлагает изменения, которые пользователь подтверждает вручную.
- Общая и персональная ленты: поиск, категории, период, сортировка, оценка связи события с компанией и объяснение этой связи.
- Разбор новости: факт публикации, механизм влияния, потенциальный риск, возможность, следующий шаг и уточняющие вопросы. Источники и позиция банка отделены от персональной интерпретации.
- Банковская библиотека: поиск и чтение материалов, добавление текста, редактирование и удаление. Индивидуальные оценки для пары «профиль — новость» доступны в отдельном редакторе рекомендаций.
- Рыночные данные MOEX: валюты, акции и металлы, история инструментов и связь с профилем компании.
- Чаты по бизнесу и выбранной новости: продолжение диалога, поиск, переименование, удаление и повтор ответа при сбое.
- Общее обновление данных, отдельный запуск сборщиков, расписания и настройки хранения.

## Быстрый запуск в Windows

Нужны Python 3.11+ и Node.js с npm. В CI используются Python 3.11 и Node.js 22. При первой установке нужен доступ к репозиториям пакетов.

Все команды ниже выполняются из каталога `NewBad`. Если `.env` ещё нет, создайте его из шаблона:

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
.\Windows_start.bat start
```

Без аргументов [Windows_start.bat](Windows_start.bat) открывает меню. Доступны также:

```powershell
.\Windows_start.bat stop
.\Windows_start.bat restart
```

Запуск использует существующие `.env` и базы, не очищает данные и не пересоздаёт аккаунты. Скрипт [scripts/dev.ps1](scripts/dev.ps1) создаёт `.venv`, устанавливает недостающие Python-зависимости и зависимости интерфейса, запускает API с автоперезагрузкой и Vite, затем открывает браузер. Порты 8000 и 5173 должны быть свободны.

| Адрес | Назначение |
|---|---|
| <http://127.0.0.1:5173> | Интерфейс |
| <http://127.0.0.1:8000/docs> | Описание API |
| <http://127.0.0.1:8000/api/health> | Проверка доступности API |

На новой установке нет аккаунтов и внешних новостей. Корпус банковской аналитики устанавливается автоматически. Аккаунты, профили и история существующей установки находятся в рабочей базе и не создаются из исходников; пароли пользователей в README не публикуются.

## Быстрый запуск в Linux

Нужны Python 3.11+ с модулем `venv`, Node.js и npm (для проверки используется Node.js 22). В Debian/Ubuntu модуль окружений устанавливается пакетом `python3-venv`. При первой установке нужен доступ к репозиториям пакетов.

Из каталога `NewBad`:

```bash
bash Linux_start.sh
```

[Linux_start.sh](Linux_start.sh) открывает меню запуска, остановки, перезапуска и проверки состояния. Можно передать команду напрямую:

```bash
bash Linux_start.sh start
```

Скрипт создаёт `.env` из `.env.example`, если файла ещё нет, подготавливает окружение Python и устанавливает зависимости интерфейса через `npm ci`. Существующие `.env`, аккаунты и базы сохраняются. Если проект перенесён с Windows вместе с `.venv`, Linux использует отдельную `.venv-linux`. Зависимости интерфейса переустанавливаются для текущей ОС и архитектуры. Проверьте абсолютные пути в перенесённом `.env`: пути Windows нужно заменить путями Linux.

**Вывод API и интерфейса идёт в текущую консоль. `Ctrl+C` или закрытие терминала останавливает оба сервера.** Файлы логов запуска не создаются. При сбое одного сервера скрипт завершает второй. После изменения кода или `.env` нужен перезапуск; автоматическая перезагрузка API в Linux-скрипте отключена.

Порты и адреса те же: интерфейс — <http://127.0.0.1:5173>, API — <http://127.0.0.1:8000/docs>. В графической сессии скрипт пробует открыть браузер; при запуске без рабочего стола адрес открывается вручную. Серверы слушают только `127.0.0.1`.

Из другого терминала можно проверить состояние, остановить или перезапустить сервис:

```bash
bash Linux_start.sh status
bash Linux_start.sh stop
bash Linux_start.sh restart
```

`restart` удерживает новую сессию в той консоли, где его вызвали. Скрипт останавливает только собственные процессы, проверяя PID и время создания, и сообщает о занятых посторонними процессами портах. В `.newbad-run/` находятся только служебные сведения о процессах и блокировка команд; каталог не входит в Git. Вся рабочая информация приложения остаётся в SQLite.

Для запуска через `./Linux_start.sh` сначала выполните `chmod +x Linux_start.sh`. Запуск через `bash` этого не требует.

## Отдельный запуск API и интерфейса

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
npm ci --prefix ui
```

В первом терминале:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --env-file .env --host 127.0.0.1 --port 8000 --reload --reload-dir app
```

Во втором:

```powershell
npm run dev --prefix ui
```

В Linux/macOS окружение создаётся командой `python3 -m venv .venv`, путь к его Python — `.venv/bin/python`. Команды npm те же. Автоматический `Linux_start.sh` предназначен для Linux; на macOS используйте отдельный запуск. При прямом запуске API `.env` загружается через `--env-file`; `dev.ps1` читает его самостоятельно. После изменения `.env` перезапустите API.

## Первый рабочий сценарий

1. Зарегистрируйтесь или войдите в существующий аккаунт.
2. Заполните и сохраните профиль компании. Пустое значение, ноль, «Нет» и неизвестный параметр имеют разный смысл.
3. Для работы через нейросеть выберите маршруты в **«Настройки разработки → Модели»** и сохраните настройки. По умолчанию все четыре задачи работают в `mock`.
4. Нажмите **«Обновить данные»**: загрузятся новости RSS и доступные рыночные данные.
5. Откройте ленту. Персональный подбор запускается согласно настройкам; его можно обновить вручную.
6. Выберите новость, посмотрите связь с компанией и позицию банка, запустите подробный разбор или обсуждение.

Для сбора данных, поиска по библиотеке и подбора по правилам модель не требуется. Для изучения сайта, нового подробного разбора и нового ответа в чате нужен доступный маршрут модели.

## Сбор, персональный подбор и обзор компании

Это отдельные операции:

| Операция | Что делает | Участие модели |
|---|---|---|
| «Обновить данные» | Загружает новости RSS и котировки MOEX | Не вызывает модель |
| Персональная подборка | Оценивает связь новостей с профилем и подбирает банковские фрагменты | Выбранная модель; при `mock` или отсутствии подходящего результата — правила |
| Подробный разбор новости | Объясняет влияние, риски и возможности для компании | Маршрут разбора новости |
| Чат по профилю | Отвечает с учётом компании, материалов, истории и условий из сообщений пользователя | Маршрут чата |
| Обзор компании | Собирает сохранённые результаты и подходящие рыночные сигналы | Отдельного вызова модели нет |

Общее обновление продолжается при переходе между страницами и перезагрузке браузера. По завершении открытая лента и рыночные виджеты перечитывают данные. Отдельно запустить новости и котировки можно в настройках кнопками **«Собрать сейчас»** / **«Сохранить и собрать»**. RSS предоставляет ограниченный архив; частичный результат возможен при недоступности источников.

Начальные настройки: окно новостей — 14 дней, хранение — 90 дней, максимум 500 публикаций; расписания сбора выключены. Персональный анализ запускается при первом открытии, затем вручную, максимум 30 кандидатов за запуск. Альтернативы — только ручной запуск либо запуск при открытии с новыми данными и прошедшим интервалом. Обзор компании по умолчанию обновляется вручную; можно включить обновление при открытии по интервалу. Эти параметры меняются в интерфейсе и сохраняются в SQLite.

Повторный запуск уже работающего сборщика блокируется. Общее задание обновления хранится в памяти процесса: перезапуск API прерывает его, но сохраняет уже записанные данные. Блокировки и расписания рассчитаны на один процесс API. Задания персонального анализа и их результаты хранятся в рабочей SQLite.

**«Обслуживание → Очистить базу новостей»** удаляет собранные публикации после подтверждения. Профили, аккаунты и общая аналитика банка сохраняются. Повторный сбор загружает доступные публикации; восстанавливать всю рабочую SQLite для этого не требуется.

## Модели по задачам

Маршруты задаются в **«Настройки разработки → Модели»**, сохраняются в рабочей базе и действуют для приложения. Изменение одного `LLM_MODE` в `.env` не заменяет выбор маршрута конкретной задачи.

| Название в интерфейсе | Задача | Назначение |
|---|---|---|
| Изучение сайта компании | `real.profile_site` | Предложения по заполнению профиля из публичного сайта |
| Подробный разбор новости | `real.news_report` | Интерпретация события, включая подобранную позицию банка |
| Персональная подборка | `real.news_selection` | Релевантность новостей и проверка связи банковских фрагментов с событием и компанией |
| Чат по профилю | `real.chat` | Ответы по компании или выбранной новости |

В списке доступны `mock`, локальные Gemma/Qwen и облачные маршруты, определённые в [config/llm.yaml](config/llm.yaml). Для локального маршрута нужен работающий совместимый сервер по `LOCAL_LLM_BASE_URL`; для облачного — адрес, ключ и `ALLOW_CLOUD=true`. Приложение не скачивает веса и не запускает сервер модели автоматически.

Резервные правила сохраняют работу персонального подбора при отсутствии результата модели. Если модель разбора отвечает, но её ответ не проходит проверки после ограниченных повторов, возможен разбор по правилам с явным происхождением `rules`. Если текст вообще не получен, новый разбор или ответ в чате возвращает ошибку с причиной. Существующие сохранённые разборы остаются доступны, пока их контекст актуален.

### Что означают сообщения `mock` в логах

`llm_task_route_mock` и `llm_generation_no_text task=news_selection ... reason=Для задачи выбран mock; модель не вызывается` означают, что персональная подборка настроена без нейросети. Это не ошибка загрузки новостей и не пустая новостная база. В этом режиме применяются правила.

Персональный анализ обрабатывает до четырёх новостей за один пакет. Для 30 кандидатов будет восемь пакетов, поэтому сообщения могут повторяться. Чтобы использовать нейросеть, выберите модель для **«Персональной подборки»**, сохраните настройки и обновите подборку. Очищать новости не нужно.

## Аналитика банка и источники выводов

Поставляемая [data/bank/corpus.sqlite3](data/bank/corpus.sqlite3) содержит девять материалов кейса: тексты 64 страниц, метаданные, контрольные суммы и проверенные фрагменты. При инициализации она устанавливается в рабочую SQLite. Исходные PDF и внешняя папка `DATA/bank_analytics` для работы сервиса не нужны.

Раздел **«Настройки разработки → Аналитика банка»** доступен без входа в пользовательский аккаунт, как и остальные настройки разработчика. Библиотека общая для всех профилей; изменения требуют CSRF-токен, который интерфейс получает автоматически. Доступны:

- Поиск по содержанию и просмотр материалов, дат, периода, примечаний и проверенных оценок.
- **«Добавить материал»**: название, дата публикации и текст от 40 до 100 000 символов. Период, примечание и уточнение темы необязательны; по умолчанию тема определяется по тексту.
- **«Редактировать»**: изменение сведений и текста существующего материала. В исходных материалах кейса полный текст и оценки для автоматического применения редактируются отдельно. Пустое поле оценок исключает такой материал из автоматических выводов.
- **«Удалить»**: удаление из общей библиотеки после подтверждения. Материал исключается из поиска и нового подбора; фрагменты, необходимые для истории источников, сохраняются.

Ручной текст используется как предоставленная пользователем аналитика банка и помечается в библиотеке. Добавление текста не является независимой проверкой его достоверности. Правки и удаления общие для всех профилей, сохраняются после перезапуска и не отменяются обновлением поставляемого корпуса. При следующем чтении ленты персональные привязки пересчитываются с учётом версии библиотеки. Параллельное изменение материала проверяется по его редакции, чтобы не затереть чужую правку.

Автоматический подбор учитывает тему события, профиль и дату публикации. Будущие материалы не используются до публикации; при точности даты до месяца доступность считается с конца месяца. Материалы старше 180 дней доступны как исторические, но исключаются из текущих автоматических оценок. Из исходного OCR в автоматические выводы попадают только отдельно проверенные фрагменты.

В **«Рекомендациях банка»** можно выбрать профиль и новость, сохранить индивидуальную оценку или удалить её, вернув автоматический подбор. Ручная индивидуальная оценка имеет приоритет над автоматической и не становится общей для других компаний.

Разборы сохраняют использованные источники и отделяют позицию банка на дату материала от вывода AI для компании. Служебные метки вроде `bank:inflation:reviewed:1` хранят связь с фрагментом; они убираются из текста, показываемого пользователю, включая ранее сохранённые разборы. Названия, даты и структурированные источники сохраняются. Подробности — в [описании банковского корпуса](data/bank/README.md).

## Хранение данных и обновление схемы

| Путь по умолчанию | Содержимое |
|---|---|
| `data/app.sqlite3` | Аккаунты, профили, общие настройки, новости, котировки, банковская библиотека, персональные связи, задания анализа, разборы и чаты |
| `data/journal.sqlite3` | Журнал вызовов модели и кэш повторного воспроизведения |
| `data/bank/corpus.sqlite3` | Поставляемые материалы кейса без аккаунтов и пользовательских данных |
| `data/news/imported/` | Каталог совместимости с прежним файловым импортом; актуальные новости находятся в SQLite |

Добавленные в интерфейсе материалы записываются в `app.sqlite3`; поставляемая `bank/corpus.sqlite3` не изменяется. PDF, JSON страниц и Tesseract во время работы приложения не используются. Пароли хранятся как salted scrypt-хэши, токены сессий — как SHA-256. Доступ к личному профилю, ленте и чатам требует авторизации; изменяющие запросы пользовательского пространства также требуют CSRF-токена. Общая библиотека банка в настройках разработчика работает без пользовательской сессии, с CSRF-проверкой при изменениях.

Текущая версия схемы рабочей базы — **17**. Миграции выполняются при инициализации и сохраняют данные. Версия 17 дополняет промежуточные базы версии 16, в которых могли отсутствовать `bank_passages.position` и `bank_documents.content_hash`. Не меняйте `PRAGMA user_version` вручную: это не добавляет недостающие столбцы.

Для резервного копирования используйте SQLite backup API либо остановите API перед копированием баз. При переносе на другую машину сохраните рабочую базу, журнал и необходимый локальный `.env` отдельно от исходников. Рабочие базы, секреты, веса, резервные копии и временные результаты не включаются в Git; поставляемый банковский корпус входит в проект.

Команды обслуживания из корня:

```powershell
.\.venv\Scripts\python.exe scripts/prepare.py check
.\.venv\Scripts\python.exe scripts/prepare.py news
.\.venv\Scripts\python.exe scripts/prepare.py bank
```

`check` инициализирует базы и показывает число новостей; без аргумента выполняется то же действие. `news` собирает RSS с сохранёнными параметрами. `bank` устанавливает корпус и обновляет персональные связи. Эти команды используют переменные окружения терминала, `.env` автоматически не читают. При нестандартных путях баз задайте соответствующие переменные перед запуском.

## Настройки сервера

Образец параметров находится в [.env.example](.env.example). Секретный ключ указывается только в локальном `.env`.

| Параметр | Назначение |
|---|---|
| `APP_DB_PATH` | Рабочая база; по умолчанию `data/app.sqlite3` |
| `DATA_DIR` | Каталог журнала; по умолчанию `data`. Не переносит `app.sqlite3`, для неё служит `APP_DB_PATH` |
| `BANK_CORPUS_PATH` | Поставляемая база банка; по умолчанию `data/bank/corpus.sqlite3`. Пустое значение отключает установку корпуса |
| `LOCAL_LLM_BASE_URL` | Совместимый с OpenAI API адрес локального сервера модели |
| `CASE_LLM_BASE_URL`, `CASE_LLM_API_KEY` | Адрес и ключ облачного провайдера |
| `ALLOW_CLOUD` | Разрешение облачных вызовов; дополнительно нужен выбранный маршрут задачи |
| `LLM_MODE` | Общий режим маршрутизатора; для рабочих задач действуют маршруты из интерфейса |
| `LLM_PLACEMENT` | Политика размещения локальной модели: `auto`, `gpu` или `ram` |
| `LLM_LOG_CONTENT` | Подробное логирование содержимого вызовов модели |
| `APP_ENV`, `AUTH_REGISTRATION_ENABLED`, `AUTH_COOKIE_SECURE` | Окружение, доступность регистрации и параметры cookie |

Относительные пути рабочих баз и корпуса считаются от корня проекта. Изменения маршрутов через интерфейс сохраняются в SQLite; ключи и разрешение облака задаются на сервере.

Скрипт [scripts/llama-server.ps1](scripts/llama-server.ps1) предназначен для отдельного локального запуска Gemma из заранее размещённого `models/gemma-4-26B_q4_0-it.gguf`. Он требует `llama-server` с CUDA, дискретную NVIDIA и проверяет доступную видеопамять. Его адрес — `http://127.0.0.1:8080/v1`; согласуйте с ним `LOCAL_LLM_BASE_URL`, поскольку шаблон `.env` указывает порт 11434. Веса скрипт не скачивает.

## Docker

```powershell
docker compose up --build
```

[docker-compose.yml](docker-compose.yml) запускает API на порту 8000 и подключает `./data` и `./config`. Интерфейс запускается отдельно: `npm ci --prefix ui`, затем `npm run dev --prefix ui`. Сборка интерфейса выполняется командой `npm run build --prefix ui`, результат — `ui/dist/`; текущий API эти файлы не обслуживает.

Compose передаёт в контейнер перечисленные в нём параметры LLM, включая ключ и разрешение облака. Остальные параметры локального `.env` автоматически внутрь контейнера не попадают; при необходимости добавьте их в `environment`. Для локальной модели на хосте используйте адрес с `host.docker.internal`, например `http://host.docker.internal:8080/v1`, а не `127.0.0.1` контейнера. PDF не монтируются.

## Проверки

Проверка «Сайт и источники» на МТС, Kaspersky и «Магните», результаты и ограничения описаны в
[отчёте по профилям](docs/profile-site-audit.md). Для повторения с настроенной моделью:
`.\.venv\Scripts\python.exe scripts/audit_profile_sites.py --output .qa/sites-check.json`.
Сценарий создаёт отдельную тестовую базу; обращается к реальным сайтам и использует настроенную модель.

При установленных зависимостях:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check app tests scripts/prepare.py scripts/build_bank_corpus.py scripts/start_linux.py
npm run build --prefix ui
```

Тесты Python используют временные базы и не изменяют рабочие аккаунты. Проверяются, в частности, миграции, сохранность банковских правок, поиск, источники разборов, персональные связи и авторизация. Проверки Linux-лаунчера включают остановку по `Ctrl+C` и `SIGHUP`, сбой запуска и завершение одного сервера; проверки процессов выполняются только в Linux, в том числе в Ubuntu CI. Синтаксис оболочки проверяется командой `bash -n Linux_start.sh`. [scripts/test.ps1](scripts/test.ps1) и [scripts/test.sh](scripts/test.sh) устанавливают зависимости, запускают Python-тесты и сборку интерфейса.

Браузерные сценарии используют Playwright и Vite на порту 5175. Путь к установленному пакету Playwright передаётся первым аргументом:

```powershell
npm run dev --prefix ui -- --port 5175
```

В другом терминале из корня проекта:

```powershell
node ui/tests/chat-workspace.mjs "<путь к пакету playwright>"
node ui/tests/data-refresh.mjs "<путь к пакету playwright>"
```

Оба сценария подменяют API и не требуют реальных аккаунтов или моделей. Используется браузер Edge; для чата доступна переменная `CHAT_QA_BROWSER`.

[ui/tests/bank-analytics.mjs](ui/tests/bank-analytics.mjs) дополнительно проверяет просмотр, создание, редактирование и удаление без входа, ошибки сохранения и мобильную вёрстку. Ему нужен **отдельный API с новой тестовой SQLite**: сценарий изменяет и удаляет материалы библиотеки, поэтому его нельзя направлять на рабочую базу. Задайте тестовому серверу `APP_DB_PATH` и `DATA_DIR` внутри `data/cache/`, запустите его, например, на порту 18000, а в терминале сценария укажите адрес:

```powershell
$env:BANK_QA_API = "http://127.0.0.1:18000"
node ui/tests/bank-analytics.mjs "<путь к пакету playwright>"
```

Для повторного прогона банковского сценария нужна новая тестовая база с девятью исходными материалами. Его снимки находятся в `ui/test-results/` при запуске из корня. Сценарии чата и обновления данных сохраняют снимки в `test-results/` относительно текущего каталога; для чата путь можно изменить через `CHAT_QA_OUTPUT_DIR`.

## Частые проблемы

| Симптом | Что проверить |
|---|---|
| `ECONNREFUSED` в Vite или интерфейс не получает данные | Работает ли API на порту 8000; посмотрите вывод API (в Linux — текущая консоль, в Windows — окно `NewBad API logs`) и `/api/health` |
| `llm_task_route_mock` / `llm_generation_no_text` при персональном подборе | Маршрут «Персональная подборка». При выбранном `mock` это ожидаемое выполнение без нейросети |
| Выбрана облачная модель, но ответ не получается | Серверные `CASE_LLM_BASE_URL`, `CASE_LLM_API_KEY`, `ALLOW_CLOUD` и сохранённый маршрут нужной задачи |
| `no such column: c.position` или отсутствует `content_hash` | Обновите код и перезапустите API, чтобы выполнилась миграция 17. Проверьте, что используется нужный `APP_DB_PATH`; не сбрасывайте рабочую базу |
| После обновления корпуса возвращаются старые оценки | Откройте ленту заново; автоматические связи зависят от версии корпуса. Ручная индивидуальная оценка сохраняет приоритет, пока её не удалить в редакторе рекомендаций |
