# NewBad — «Что важно для вашей компании»

Прототип новостной аналитики для руководителя компании (Альфа-Хак 2026, кейс Changellenge × Альфа-Банк). Сервис собирает профиль, ставит новости в персональный порядок и открывает карточку из трёх слоёв: факт, позиция аналитиков банка, вывод модели. У карточки есть цитата со страницей, пропуски профиля и уточняющий вопрос.

**Статус на 22 октября 2026.** Демонстрационный сценарий работает в режиме `mock`: три синтетические компании, вход по компании, лента, карточка ставки 14%, чат и вставка своей новости. Ключ API и видеокарта для этого пути не нужны. Облачный вызов на живом ключе в этом прогоне не подтверждался. Страница «Настройки разработки» меняет режим текущего процесса и не переписывает `.env`. Форма «уточнить профиль» в интерфейсе отсутствует.

## Что проходит в демо

1. Открыть http://127.0.0.1:5173 — экран «Альфа-Бизнес».
2. Открыть «Что важно для вашей компании». Если компания ещё не выбрана, откроется вход.
3. Войти компанией. На экране видны название и роль: заёмщик, вкладчик или компания без кредита и депозита. В демо это `U-BORROWER`, `U-SAVER` и `U-PEER`.
4. Открыть новость «Ключевая ставка сохранена на уровне 14%». У заёмщика и вкладчика тексты карточки разные.
5. Проверить ссылку новости и цитату банка со страницей.
6. Задать вопрос по карточке. В режиме `mock` ответ собирается по уже открытой карточке. Происхождение, режим и число повторов лежат в «Как получен вывод».

Классификацию события и порядок ленты считает код: правила и BM25. Модель, когда она включена, выбирает узкий список инструментов, извлекает факт из вставленной новости, пишет текст карточки и отвечает в чате. Если вызов не удался или проверка цитаты и чисел не прошла, на экране остаётся шаблонная карточка.

## Запуск с чистого окружения

Нужны Python 3.11, Node.js и npm. Команды ниже — для PowerShell из каталога `NewBad`.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
python scripts\prepare.py
.\.venv\Scripts\python.exe -m pytest -q
.\scripts\dev.ps1
```

`python scripts\prepare.py` только проверяет демо-набор и в сеть не ходит. Ожидаемый текст:

```text
демо-компании: есть
новости: 10
паспорта банка: 1
демо-набор на месте, ключ и видеокарта не нужны
```

В `.env` для этого пути оставьте `LLM_MODE=mock`, `ALLOW_CLOUD=false`, `PROFILE_SOURCE=demo` и пустой `CASE_LLM_API_KEY`. Скрипт `scripts\dev.ps1` читает `.env`, поднимает API на http://127.0.0.1:8000 и интерфейс на http://127.0.0.1:5173. Описание API: http://127.0.0.1:8000/docs. Прокси Vite отправляет `/api` на порт 8000. Если виртуального окружения или `ui/node_modules` ещё нет, `dev.ps1` создаёт их сам.

Двойной щелчок по `start-manual.bat` открывает меню: 1 запустить, 2 остановить, 3 перезапустить. Остановка закрывает API и интерфейс этого проекта. Контейнер `newbad-demo` тоже останавливается, если именно он держит порт. Чужой процесс на порту скрипт не завершает. Из командной строки то же самое: `start-manual.bat stop` и `start-manual.bat restart`.

На Unix активация другая: `source .venv/bin/activate`. Дальше те же команды `pip`, `prepare.py` и `pytest`. Скрипт `dev.ps1` рассчитан на Windows.

### Контейнер

Образ содержит API, демо-CSV, 10 новостей и паспорт ставки. Интерфейс и файл `.env` в образ не копируются.

```powershell
docker build -t newbad:demo .
docker run --rm -p 8000:8000 -e LLM_MODE=mock -e ALLOW_CLOUD=false -e PROFILE_SOURCE=demo -e CASE_LLM_API_KEY= newbad:demo
```

Во втором окне, в каталоге `ui`:

```powershell
npm install
npm run dev
```

`docker compose up --build` публикует тот же порт 8000 и по умолчанию тоже ставит `mock`, `ALLOW_CLOUD=false` и `PROFILE_SOURCE=demo`. Compose читает `.env` проекта и передаёт `CASE_LLM_API_KEY` в окружение контейнера, если ключ там задан. В слои образа ключ не попадает. Compose монтирует `./data`, `./config`, `../DATA/company_profile` и `../DATA/bank_analytics`. Если закрытых каталогов рядом нет, для чистого демо используйте `docker run` выше: демо-набор уже внутри образа.

## Обновлённая карточка и сбор публикаций (24 октября 2026)

Реальная карточка разделяет **исходные факты публикации** и **аналитическую оценку для компании**. Показываются индекс связи, объяснения по полям профиля, риски, возможности, возможное действие и вопросы для уточнения. Источник и происхождение разбора сохраняются; кнопки запуска/повтора анализа и чат работают как раньше.

Шкала оценки: меньше 30/100 — связь не подтверждена; 30–54 — «Слабая связь»; 55–79 — «Есть связь»; 80–100 — «Сильная связь». Индекс — не вероятность события. Совпадение одного общего слова больше не создаёт высокий балл. Правила используют независимые признаки из профиля и новости, а модель может лишь дополнить обоснованную оценку. Изменение версии ранжирования требует нового анализа; старые новости и профили не удаляются.

Для новых установок окно RSS-сбора увеличено с 3 до 14 дней (максимум 30). Уже сохранённые пользовательские настройки не перезаписываются, их можно изменить в «Настройках разработки». Парсер сначала отсекает старые записи, приоритетно загружает полные тексты свежих статей, безопасно обрабатывает HTTPS-перенаправления, умеет читать RSS и Atom и отличает разные новости с похожими названиями. Пустое содержание не заменяется придуманным текстом заголовка.

В статусе сбора показаны число RSS-записей, обращения к HTML-страницам, импортированные материалы, дубли, записи вне периода и записи, отклонённые из-за качества. Количество новых материалов ограничено реальными публикациями официальных лент, выбранным периодом и полнотой предоставленных источников.

## Настройки разработчика и сбор новостей (25 октября 2026)

Настройки разделены на «Новости», «Модели», «Рыночные данные», «Персонализация» и «Обслуживание». Изменения всех разделов сохраняются общей кнопкой; «Сохранить и собрать» сначала сохраняет выбранные параметры, затем запускает сбор. Несохранённые изменения можно отменить. Очистка базы и сброс тестового режима находятся в обслуживании и требуют подтверждения.

В новостях доступны быстрые периоды 3/7/14/30 дней, количество материалов в базе и в сохранённом периоде, итоги последнего запуска и отдельный раскрывающийся отчёт по каждому источнику. Срок хранения не может быть меньше периода сбора. Сохранённое ранее короткое окно можно увеличить вручную; настройки существующих установок автоматически не переписываются.

Каталог содержит 8 лент: четыре Банка России, ФНС (публичная лента региона 77), «Ведомости — экономика», «Ведомости — бизнес» и «Ведомости — финансы». Для деловых СМИ используются только опубликованные RSS-тексты и ссылки, без загрузки полных статей. Записи без содержания пропускаются. RSS отдаёт ограниченный архив: увеличение периода не гарантирует загрузку всех публикаций за этот срок. Лента «Новое на сайте» Банка России также содержит разделы, таблицы и файлы, которые не всегда являются самостоятельными статьями.

Сборщик переиспользует HTTP-соединения и страницы с разными якорями, отдаёт приоритет новым URL перед дополнением коротких сохранённых текстов и повторно использует уже сохранённый полный текст. Лимит — до 120 загрузок страниц и 90 секунд на загрузку статей одного источника (текущий HTTP-запрос может завершиться позже). Достижение лимита и сетевые ошибки отражаются отдельно в диагностике. Извлечение текста поддерживает страницы с общей HTML-формой и отделяет контейнер статьи от навигации сайта. Параллельный повторный сбор и очистка базы во время сбора блокируются; при нескольких процессах сервера блокировка действует внутри каждого процесса.

## Реальный режим: локальный аккаунт (этап B)

В реальном режиме доступны локальные регистрация, вход, выход и ручное заполнение профиля бизнеса. Публичный сайт можно проанализировать: модель предложит поля с цитатами, а пользователь подтвердит их вручную. Аккаунты, профиль, настройки сбора и собранные новости хранятся в `data/app.sqlite3` (путь можно переопределить через `APP_DB_PATH`); демо-новости остаются JSON-файлами в репозитории. При запуске API создаёт схему базы; пароли хранятся как salted scrypt-хэши, в cookie сессии выдаётся случайный токен, а в SQLite сохраняется только его SHA-256. Запросы регистрации, входа, выхода и сохранения профиля используют CSRF-токен; неудачные попытки ограничиваются по IP и логину.

### Помощник по публичному сайту

1. В реальном режиме откройте **«Профиль компании»**, укажите сайт и сохраните изменения.
2. Подтвердите согласие на обработку публичных страниц выбранной моделью и нажмите **«Изучить сайт и предложить заполнение»**. При облачном маршруте текст страниц передаётся внешнему провайдеру.
3. Обход сайта ограничен по времени, объёму, глубине и количеству страниц; соблюдает robots.txt, допускает только публичные адреса и не уходит на произвольные сторонние сайты. Страницы «О компании», услуги, товары и контакты получают приоритет.
4. После завершения виден перечень прочитанных страниц и предложения по пустым полям. Каждый пункт содержит цитату, страницу-источник и приблизительную уверенность модели. Можно **принять**, **отклонить** или **явно принять все** — без этих действий профиль не меняется.
5. Для ранее подтверждённых сведений доступен раскрываемый список **«Подтвержденные данные с сайта»** с цитатами и ссылками. Если человек редактирует значение вручную, старый источник больше не отображается как доказательство нового значения.

Сайт может подтверждать описание компании, её деятельность, продукты, клиентов, географию рынков и зависимости, но не должен автоматически выставлять потребности в банковских услугах, налоговые показатели или предположения о финансовом состоянии. Поля, которые сайт не подтверждает, остаются пустыми и вводятся вручную. Любые предложения модели могут содержать ошибки и требуют проверки. Повторное сканирование ограничено интервалом безопасности.

Для локальной разработки включена регистрация (`APP_ENV=development`, `AUTH_REGISTRATION_ENABLED=true`). В production регистрация по умолчанию выключена; включать её до настройки восстановления пароля, подтверждения аккаунта и мер эксплуатации нельзя. `AUTH_COOKIE_SECURE` должен быть включён за HTTPS. Демо-режим остаётся отдельным и использует прежний сценарий.

Настройки для локального запуска находятся в `.env.example`; создайте `.env` копированием этого шаблона. База SQLite и её WAL/SHM/резервные файлы исключены из Git.

## Режимы модели

Режим задаётся переменной `LLM_MODE` до старта процесса. Страница «Настройки разработки» задаёт маршруты моделей отдельно для каждой задачи и параметры сбора/хранения данных. Общий режим `LLM_MODE`, разрешение облака `ALLOW_CLOUD` и размещение `LLM_PLACEMENT` настраиваются на сервере через окружение (`.env`/конфигурацию запуска), а не через интерфейс. Если для задачи выбран «Общий режим», используется серверный `LLM_MODE`. Облачные маршруты работают только при `ALLOW_CLOUD=true` и заданном на сервере `CASE_LLM_API_KEY`. Список разрешённых имён — в [config/llm.yaml](config/llm.yaml).

| Режим | light | heavy | Облако |
|---|---|---|---|
| `mock` | заглушка, модель не вызывается | заглушка | выключено |
| `local_only` | локальная Gemma | локальная Gemma | выключено |
| `local_dual` | локальная Gemma | локальный Qwen3.6 | выключено |
| `hybrid` | локальная Gemma | облачный Qwen3.6, при сбое локальная Gemma | нужен `ALLOW_CLOUD=true` |
| `cloud_only` | облачная Gemma | облачная Gemma | нужен `ALLOW_CLOUD=true` |
| `replay` | ответ из локального кэша | ответ из локального кэша | в сеть не ходит |

`light` — один короткий выбор инструментов из списка, который уже собрал код. `heavy` — факт вставленной новости, текст карточки и ответ в чате. В `mock` эти вызовы остаются шаблоном.

Локальный сервер — OpenAI-совместимый адрес `LOCAL_LLM_BASE_URL`. Скрипт `scripts\llama-server.ps1` поднимает Gemma на `127.0.0.1:8080`, если в `models\` лежит официальный GGUF и на дискретной NVIDIA свободно около 14800 МиБ. Файл весов в Git не входит, скрипт его не скачивает. Если веса уже стоят в Ollama, адрес задают так: `LOCAL_LLM_BASE_URL=http://127.0.0.1:11434/v1`.

В облако уходят только точные id из инструкции кейса. Локальные назначения в конфигурации — Gemma и Qwen3.6. GLM, DeepSeek, Kimi и Qwen3-VL в локальный сервер не отправляются. Qwen3-VL в текущем сценарии не вызывается.

Для облачной генерации запрашивается JSON-объект; карточка принимает вывод только после проверки источников и разрешённых id доказательств. Если формат или проверка не пройдены, интерфейс показывает шаблонный ответ и отмечает его происхождение.

В `config/llm.yaml` записаны потолок провайдера 500 ₽ в сутки и внутренний потолок 400 ₽, сброс в 03:00 по Москве. Цены за токен в инструкции нет, поэтому `rub_per_1k_tokens` равен 0. Стоимость запроса считается как токены × эта ставка и в демо равна 0. Повтор проверки карточки ограничен двумя попытками.

Из каталога `NewBad`, с активированным `.venv`:

```powershell

.\.venv\Scripts\python.exe -m ruff check app tests eval scripts/prepare.py
```

`pytest` поднимает приложение в процессе и к облаку не обращается. Ожидается успешное завершение. Прогон 22 октября 2026: `178 passed` и 6 предупреждений Starlette и PyMuPDF. `ruff` и `tsc --noEmit` завершились без замечаний.

Сценарии «компания → лента → карточка → вопрос» и ошибки источника лежат в `tests/e2e/`. Измерения ссылок, precision@3, nDCG@5, дублей, покрытия PDF, задержки и стоимости — в [eval/README.md](eval/README.md).

## Ограничения

- Живой облачный ответ и сравнение моделей на ключе кейса в этот прогон не входят. Для демонстрации остаётся `mock`.
- При ставке 0 рублёвый счётчик не растёт, и запрос по накопленной сумме не останавливается. Облако при этом закрыто, пока `ALLOW_CLOUD` не равен `true`.
- Общий режим модели и размещение локальной модели задаются через окружение сервера; экран настроек управляет маршрутами задач и параметрами данных. Изменение этих переменных не записывает ключ в `.env`. `ADMIN_TOKEN` и `DEMO_MODE` есть в `.env.example` и в Compose, код приложения их не читает.
- Отдельной формы, чтобы дописать профиль компании, нет. Пропуски показаны в карточке как «Неизвестно: …».
- В чате дополнительный поиск начинается с фраз вроде «найди» или «поищи» и для одной карточки выполняется не больше двух раз.
- `local_dual` назначает тяжёлые ответы на Qwen3.6. Для такого локального запуска нужна видеокарта примерно от 24 ГБ. Скрипт `llama-server.ps1` эту модель не стартует.
- Образ Docker собран без `data/bank/extracted`. На хосте те же новости могут получить больший вес за страницу банка, чем в контейнере.
- Повторный `python scripts\prepare.py bank` заново читает PDF. Для демо это не требуется.

## Запуск всех проверок

Из корня репозитория скрипт сам подготовит Python-окружение, установит зависимости для разработки и frontend-зависимости, затем выполнит все Python-тесты и проверку TypeScript со сборкой UI. Нужны Python 3.11+ и Node.js LTS с npm; для первой установки нужен доступ к пакетным репозиториям.

**Windows PowerShell:**
```powershell
git pull origin develop
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\test.ps1
```

**Linux / macOS:**
```bash
git pull origin develop
bash scripts/test.sh
```

Скрипт создаёт локальное окружение `.venv` (если его ещё нет) и использует `ui/package-lock.json` через `npm ci`. Повторный запуск можно выполнять той же командой. Если любая установка, тест или сборка завершается ошибкой, скрипт остановится и покажет ошибку; финальное сообщение об успехе появляется только после прохождения всех этапов.
