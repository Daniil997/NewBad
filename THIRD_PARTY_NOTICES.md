### PyMuPDF и MuPDF

По [документации издателя](https://pymupdf.readthedocs.io/en/latest/about.html) PyMuPDF и MuPDF доступны по AGPL либо коммерческой лицензии; установленный `pymupdf-1.26.4.dist-info/COPYING` также указывает двойное лицензирование. Условия размещены на [странице лицензирования PyMuPDF](https://pymupdf.io/licensing).

Рабочий сервис читает банковские материалы из SQLite и не открывает исходные PDF. Однако PyMuPDF остаётся в `requirements.txt`, импортируется модулем подготовки PDF и устанавливается в текущий Docker-образ. Переход данных в SQLite сам по себе не исключает компонент из поставки и не отменяет его лицензии. При использовании AGPL-сборки применяются её условия, включая требования к предоставлению соответствующего исходного кода в предусмотренных лицензией случаях; альтернативный вариант — соответствующая коммерческая лицензия Artifex. Наличие такой коммерческой лицензии этим файлом не подтверждается.

## Модели и облачный API

Разрешённые имена перечислены в [config/llm.yaml](config/llm.yaml), маршруты рабочих задач выбираются в настройках разработчика и сохраняются в SQLite. Веса моделей не включаются в проект или Docker-образ и не скачиваются приложением. Режим `mock` модель не вызывает.

Для локальных вариантов, названных в конфигурации:

| Модель / имя маршрута | Проверенный источник | Лицензия опубликованного upstream-артефакта |
|---|---|---|
| Gemma 4 26B A4B; API-ID `google/gemma-4-26b-a4b-it`, локальный псевдоним `gemma-4-26b-a4b` | [Официальная карточка Google `gemma-4-26B-A4B-it`](https://huggingface.co/google/gemma-4-26B-A4B-it) | Apache-2.0 |
| Qwen3.6 35B A3B; API-ID `qwen/qwen3.6-35b-a3b`, локальный псевдоним `qwen3.6-35b-a3b` | [Официальный LICENSE Qwen3.6-35B-A3B](https://huggingface.co/Qwen/Qwen3.6-35B-A3B/blob/main/LICENSE) | Apache-2.0 |

Эти сведения относятся к указанным опубликованным моделям. Для отдельной квантизации, GGUF или другого преобразованного файла учитываются его конкретный источник, ревизия и сопровождающие уведомления. Лицензия программы запуска модели не заменяет лицензию её весов.

В списке облачных маршрутов также находятся `z-ai/glm-5.3-flash`, `deepseek/deepseek-v4.1-flash`, `moonshotai/kimi-k2.6` и `qwen/qwen3-vl-30b-a3b-instruct`. В проекте это идентификаторы запросов к настроенному API, а не поставляемые наборы весов. По одному такому идентификатору этот документ не устанавливает лицензию весов и не удостоверяет состав модели за шлюзом. Для облачных вызовов действуют условия используемого провайдера; требуется настроенный адрес, серверный ключ и разрешение облака.

При облачном маршруте провайдер получает переданный модели контекст: необходимые сведения о компании, тексты новостей, выбранные банковские фрагменты и, для чата, сообщения в пределах передаваемой истории. Сохранение данных в локальной SQLite не означает, что весь анализ выполняется локально. Содержимое вызовов также может попадать в журнал и подробные логи согласно настройкам.

## Внешние инструменты

Эти инструменты не устанавливаются из `requirements.txt` или `ui/package-lock.json` и не включаются в текущий Docker-образ приложения как отдельные программы.

| Компонент | Лицензия / источник | Использование в проекте |
|---|---|---|
| Tesseract OCR | [Apache-2.0](https://github.com/tesseract-ocr/tesseract/blob/main/LICENSE) | Внешняя программа для отдельного OCR исходников; функции вызова находятся в `app/ingest/bank_documents.py` |
| Официальные языковые данные Tesseract, включая `rus.traineddata` | [Apache-2.0, tessdata](https://github.com/tesseract-ocr/tessdata/blob/main/LICENSE) | Локальные языковые файлы в `data/tessdata/` исключены из Git и Docker; для готового корпуса не нужны |
| llama.cpp / `llama-server` | [MIT](https://github.com/ggml-org/llama.cpp/blob/master/LICENSE) | Необязательный внешний сервер модели; запуск заранее размещённых весов через `scripts/llama-server.ps1` |
| Ollama | [MIT для программы Ollama](https://github.com/ollama/ollama/blob/main/LICENSE) | Возможный внешний совместимый сервер по `LOCAL_LLM_BASE_URL`; не делает лицензии всех загруженных моделей одинаковыми |
| Playwright | [Apache-2.0](https://github.com/microsoft/playwright/blob/main/LICENSE) | Внешний пакет для сценариев `ui/tests/*.mjs`; путь к установленному пакету передаётся аргументом |

`python scripts/prepare.py bank` устанавливает готовый банковский корпус из SQLite и обновляет персональные связи. Команда не запускает Tesseract и не требует PDF или `rus.traineddata`. Скрипт `scripts/build_bank_corpus.py` отдельно собирает поставляемую SQLite из подготовленных результатов OCR и метаданных. Браузеры для Playwright и системные компоненты внешних серверов имеют собственные условия распространения и не описываются лицензией самого Playwright или llama.cpp.

Смена PDF на текст в SQLite не отменяет права на содержание исходных материалов. Поставляемый банковский корпус сохраняет банковские тексты, даже несмотря на отсутствие самих PDF. Условия распространения приложения, программных библиотек, моделей и банковских текстов рассматриваются отдельно.

### Какие файлы входят в поставку

- `data/bank/corpus.sqlite3` — поставляемые данные кейса: предусмотрено исключение в `.gitignore` и `.dockerignore`, файл включается в Docker-образ через `COPY data`.
- `data/app.sqlite3`, `data/journal.sqlite3`, WAL/SHM и резервные копии — локальные рабочие данные, исключённые из Git и контекста Docker-сборки. В Docker Compose рабочий каталог `data` подключается с хоста.
- Локальный `.env` с ключами и секретами исключён из Git и Docker-сборки; пример настроек находится в `.env.example`.

Дополнительные сведения: [README.md](README.md), [хранение данных](data/README.md), [банковский корпус](data/bank/README.md). При изменении зависимостей, моделей, источников или состава поставки этот перечень нужно сверить с конкретными дистрибутивами заново.
