# Архитектура

```
Источники             Ядро                               Интерфейс
CSV клиентов ─┐   ┌─ profile (признаки, экспозиции) ─┐
PDF банка ────┼─ ingest ─┤  retrieval (BM25)            ├─ scoring ─ agent ─ api ─ ui
Новости ──────┤   └─ граф платежей ─────────────────┘      │
Ввод клиента ─┘                                            └─ llm (провайдеры, режимы, бюджет)
                                                             tracing (журнал)
```

| Модуль | Ответственность |
|---|---|
| `app/ingest` | загрузка CSV, PDF банка, новостей; очистка, дедупликация, классификация, извлечение фактов |
| `app/profile` | признаки компании с происхождением, производные признаки, экспозиции |
| `app/retrieval` | BM25-индекс новостей и материалов банка |
| `app/scoring` | ранжирование событий по формуле из `config/scoring.yaml`, объяснение балла |
| `app/agent` | цикл PLAN, GATHER, DRAFT, VERIFY, REVISE, FINALIZE; белый список инструментов |
| `app/llm` | единый клиент, провайдеры, режимы, кэш, бюджет, белый список моделей |
| `app/tracing` | журнал вызовов инструментов и моделей (SQLite) |
| `app/schemas` | схемы профиля, события и карточки |
| `app/api` | HTTP API для интерфейса |

## Инварианты

1. Отбор и ранжирование делает код, LLM пишет интерпретацию только по отобранному.
2. Каждый тезис карточки имеет слой (`confirmed_fact`, `bank_position`, `model_inference`), источники и признаки.
3. Каждый признак компании хранит происхождение: `bank_data`, `user_input`, `website`, `derived`.
4. Агент вызывает только четыре инструмента: `get_profile`, `search_news`, `search_bank_analytics`, `get_counterparties`.
5. Приложение не обращается к моделям напрямую, только через `LLMRouter`. Другие модели, кроме списка кейса, отклоняются.
6. В режимах `local_only`, `local_dual`, `mock`, `replay` облачные вызовы запрещены на уровне маршрутизатора.
7. В промпт попадают только поля из `config/prompt_fields.yaml`.
